1. 官方哈希看**发行页**，或本文件末尾由 CI 追加的「本次发行构建记录」。
   不要拿本机自构建的哈希去比对：每次构建的时间戳不同，哈希必然不同，这不代表文件损坏。

最近一次发行：v1.0.5
---------------------------------------------------------
（push 到 main 即自动递增发行版号并发布，详情见 Release 页与 README）

这一版新增 / 修复：
  · 配置文件版本校对 + 自动补齐
      - 配置文件带 config_version（当前 v4：v1 鉴权 / v2 聊天开关 / v3 勘探+命令 / v4 空置域挖掘）
      - 文件版本低于插件支持版本 → 自动补齐缺失项（按默认值写回）并盖上 v4
      - 账号信息（littleskin_players / offline_players）与已有配置值**一律原样保留**
      - 文件版本高于支持版本 → 只读不写，避免把新字段抹掉
      - /hy status 显示配置文件版本；写回用"临时文件 + 原子替换"，且等读取器关闭后再做（Windows 兼容）
  · 命令语义收敛 —— 不再需要管理员手抄 UUID
      /hy add off <名字…>        先查户口：有历史身份（usercache / 存档 / 原版离线算法）就沿用，
                                 没有才发新 UUIDv7 并查重
      /hy off <名字…> force      唯一会"换人"的一条：给新 UUIDv7，并警告老存档不跟过去
      /hy del <名字…>            按名字删（名字唯一，不分外置/离线）
      去掉了没有意义的"手填 UUID"写法（/hy off <名字> <uuid>、/hy add off <名字> <uuid>）与 +/− 别名
  · README 整篇重写（2008 行 → 479 行）：文首即**命令汇总表**与 **GPL-3.0-or-later** 声明
  · CI / Release 改用 Java 25（与服务端运行时一致）
  · 修掉一个让 CI 必挂的坑：.gitignore 里 `world/` 没锚定到仓库根，
    把自检替身 verify/lag/net/minecraft/world/** 下 4 个文件（Entity / ChunkPos / LevelChunk / Heightmap）
    静默忽略了 —— 本地有文件所以自检照过，CI 检出后缺文件、javac 秒级失败。
    现在运行时目录规则全部锚定（/world/、/logs/、/libraries/ …）并加了兜底规则。

功能总览（一个 jar，纯服务端，不用插件 / 不用客户端 Mod）
---------------------------------------------------------
  三合一登录     正版号 + LittleSkin 等外置号 + 管理员指定 UUID 的离线号，同一台原版服务端同服；
                 失败关闭（名单内校验失败直接断开，绝不回退 Mojang）、皮肤属性强制验签
                 → README 第一、六章
  区块卡顿勘探   按区块分项采样 tick 耗时（区块 tick / 实体 / 乘客 / 方块实体 / 整服 MSPT），
                 一条命令列出异常区块的**坐标范围**，聊天里点一下 tp 到现场 → README 第七章
  管理员命令     /hy …（命令根可配，另有 ha / hyauth；/lag 是勘探快捷方式）
                 名单管理 + UUIDv7 发证前扫全服查重；控制台 / 游戏内 / RCON 全覆盖，
                 不往 Brigadier 注册节点（不会与原版或插件命令撞名）→ README 第八章
  空置域挖掘     /hy clear 对角选两点 → 预演 → 确认，服务端用原版 /fill 分三阶段节流执行、可随时中止；
                 基岩开关、边长/体积上限、权限门槛更高 → README 第九章
  配置文件       littleskin_config.json，改完保存 ~0.5s 热重载；带 config_version 与自动补齐 → README 第五章
