怎么核对产物（看这三条就够）
---------------------------------------------------------
1. 官方哈希看**发行页**，或本文件末尾由 CI 追加的「本次发行构建记录」。
   不要拿本机自构建的哈希去比对：每次构建的时间戳不同，哈希必然不同，这不代表文件损坏。
2. 校验命令：
     Linux/macOS : sha256sum HyAuth-Agent-1.0.0.jar
     Windows     : (Get-FileHash .\HyAuth-Agent-1.0.0.jar -Algorithm SHA256).Hash.ToLower()
3. 升级只需替换 jar 并重启服务端；**配置文件不用动** ——
   新版本会自动补齐新增的配置项（只新增，账号信息与已有值原样保留，见 README 第五章）。

最近一次发行：v1.0.13
---------------------------------------------------------
（push 到 main 即自动递增发行版号并发布，详情见 Release 页与 README）

这一版新增 / 修复：
  · 诊断用开关 chunk_lag.block_entity_hook（v1.0.13）
      - 默认 true；设为 false 后**完全不测方块实体**（ticker 切面直接短路，连 nanoTime 都不调）
      - 用途：真机卡顿（Can't keep up / getsockopt 超时 / 玩家进不去）时，先用它或 /lag off
        排除"是不是采样开销"这一项，再去看机器与其它功能
      - 配置自动补齐会写入这一项；/hy status 的"方块实体口径"一行会反映当前状态
  · 修掉报告里的 "unknown" 维度（v1.0.12）
      - 现象：报告出现 unknown x[..] z[..] 的行，且那些行只有"方块实体"有值（区块/实体都是 0）
      - 原因：26.x 的方块实体是"维度级遍历 ticker"（Level#tickBlockEntities → 逐个
        TickingBlockEntity#tick），而 ticker（LevelChunk$RebindableTickingBlockEntityWrapper）
        只持有内层 ticker、没有任何 level 引用 ⇒ 拿不到维度
      - 修法：新增切面 LevelBlockEntityHostAdvice 挂在 Level#tickBlockEntities() 的入口/出口，
        记下"当前维度"；ticker 切面取不到 level 时退回这个上下文（服务端 tick 单线程，静态字段足够）
      - /hy status 的能力探测同时报告这条路径（net.minecraft.world.level.Level#tickBlockEntities）
  · 升级策略与配置版本号（v1.0.11）
      - config_version 改为**跟着编译版本走**：序号 = major*10000+minor*100+patch（v1.0.11 → 10011）；
        版本来源优先级：系统属性 hyauth.version → 环境变量 HYAUTH_VERSION → jar 清单 Implementation-Version → 1.0.0
      - 版本不一致时：用**当前版本的最新默认模板重写配置**，只保留用户信息
        （littleskin_players / offline_players / commands.extra_admins），其余全部回默认，
        旧文件备份为 littleskin_config.json.bak-v<旧版本>（旧的无用字段会被清掉）
      - 约定 config_version: -1 = 不触发重置（自检脚本用）
      - /hy status 会显示"配置文件版本 vN（本插件支持 vM）"与"权限判定依据"
  · 权限判定收敛为**只认原版 op 名单（ops.json）**：无实体（控制台/RCON）= 管理员；
    在 ops.json 里 = 管理员（不再纠结它记的等级数字）；其余玩家 = 0；
    commands.extra_admins 是显式信任名单（默认空，用于"我是管理员但没被 op / 换了账号"）
  · 修掉方块实体 ticker 切点误伤自己人：匹配器加上 net.minecraft.* 限定，避免把 Agent 自己的
    匿名内部类也拿去改写（会导致"字节码改写失败"并干扰聊天切面）
  · 自检同步：三套脚本/测试的配置版本与 jar 内 CONFIG_VERSION 对齐，verify/lag.ps1 现 95 项，
    四套自检（loaderiso 6/6 · chat 11/11 · lag 95 项 · verify 各 20/20）全部通过
  · 真机第三轮（v1.0.10）：权限判定修正 + 额外信任的管理员名单
      - ★ 修掉"服务端说该玩家已是管理员，插件却判成权限 0"：原来走完 26.x 的 permissions()/PermissionSet
        这条链就 return 0，**没有再往下查原版 op 名单**。现在改成多路兜底：
        commands.extra_admins → hasPermission(int)（旧版）→ permissions()/PermissionSet（26.x）→
        **PlayerList#getOps()#get(NameAndId)（就是读 ops.json，按 UUID 认人）** → 控制台/RCON 兜底
      - 新增配置 commands.extra_admins（名字或 UUID 列表，配置版本 → v5）：把"我是管理员但没被 op /
        换了个账号登录"的名字写进去即可，保存即生效（不需要 op，也不需要重启）
      - 权限不足时的提示现在会打印"服务端看到的来源（名字 / UUID）"与三种解法（/op、extra_admins、后台执行）
      - /hy status 新增"当前来源: 名字 / UUID · 权限等级 N（命令门槛 M）"一行
  · 真机第二轮（v1.0.9）：命令注册进真实命令树 + 只允许 OP/后台
      - ★ 把 /hy、/lag 与一级子命令**注册进真实的 Brigadier 命令树**（Commands 构造完成时，纯反射实现，
        切面字节码仍不引用 Brigadier/服务端类型）：OP 有 **Tab 补全**；聊天里 /hy lag 报告的"点击传送"
        改用 RunCommand（客户端认可，点一下直接执行）；普通玩家下发的命令树里没有这些命令
      - ★ 注册的节点带 requires(权限等级 ≥ commands.op_level)：**只有 OP 与控制台/RCON 能用**，
        普通玩家连补全都看不到、客户端也不会把命令发出去；服务端侧 tryHandle 仍有第二道权限检查
      - ★ 修掉"游戏内命令只有控制台有输出、聊天框空白"：游戏内走 performCommand(ParseResults,String)，
        第一个参数是 ParseResults 而不是命令来源；现在先 getContext().getSource() 取出真正的 CommandSourceStack
      - ★ 修掉传送维度错误：26.x 的 ResourceKey 没有 location()，只有 registryName(minecraft:dimension)
        与 toString()；原来取错成 minecraft:dimension，导致 /execute in minecraft:dimension run tp … 必然失败
        （却报"已传送到"）。现在从 toString 解析出 minecraft:the_nether 这种真实维度 id
      - 聊天发送兜底：探测失败时按 sendSuccess → sendSystemMessage → sendMessage 逐个真试并记住可用的那个
      - 报告：维度显示"主世界/下界/末地"；实体只数估不出时不再显示"（≈0只）"
      - /hy status 新增"命令树注册"一行；/hy reload 会按新的 roots 重新注册
      - 自检新增 Brigadier 替身与 10 项断言（命令树注册、OP 门槛、ParseResults 运行期路径、兜底执行器），
        现在共 93 项
  · 真机反馈的小修（v1.0.8）
      - /hy status 的切面能力探测补上 26.x 的方块实体路径（TickingBlockEntity#tick），
        并新增「权限判定」一行（旧 API / 26.x PermissionSet 各报告是否可用）；
        以前只探 LevelChunk#tickBlockEntities，真机上会误报"未找到"
      - 报告里维度名不再显示成 ResourceKey[minecraft:dimension / minecraft:the_nether]，
        统一抽成 minecraft:the_nether 再显示"下界/主世界/末地"
      - 报告里实体只数估算为 0 时不再显示"（≈0只）"
      - 点击传送的命令修正：命令根是 /lag 时不再拼成 /lag lag tp 1，而是 /lag tp 1
      - 未知子命令会给出拼写建议（例：/hy log → 你是不是想用 /hy lag？）
      - 聊天发送路径不再"探测失败就只打控制台"：改为逐个真试 sendSuccess → sendSystemMessage →
        sendMessage，哪个调通就用哪个（真机上出现过"探测说不可用、其实完全能用"）
      - /hy status 版本号不再是"开发版"：清单里的 Implementation-Version 现在由构建参数注入，
        发行工作流会写入真实发行版本（如 v1.0.8）
      - 方块实体 ticker 切面挂上时会在日志里打印前 5 个命中类名（便于真机确认）
  · ★ 修掉三个"真机才暴露"的静默失效（离线自检当时全绿、真机上功能整块不工作）
      1) 命令入口：26.3 的 Commands#performPrefixedCommand / performCommand 返回 **void**，
         而切面匹配器要求 int ⇒ 一个方法都没匹配上，所有 /hy 命令落到原版报"未知或不完整的命令"。
         现在按 void / int / boolean 三种返回类型分别挂切面（CommandAdviceVoid / CommandAdvice /
         CommandAdviceBoolean）。
         教训：日志里的"命中命令系统 / 已改写目标类字节码"在方法匹配为空时也会打印，不能当成功证据。
      2) 权限判定：26.3 删掉了 CommandSourceStack#hasPermission(int)，改成 permissions() →
         PermissionSet#hasPermission(Permission)（Permissions.COMMANDS_MODERATOR/GAMEMASTER/ADMIN/OWNER
         对应等级 1~4）。只走旧路径会把所有人判成 0 级 ⇒ 命令挂上了却"权限不足"。现在两条路径都试。
      3) 方块实体 tick：26.3 已移除 LevelChunk#tickBlockEntities()，改为 Level#tickBlockEntities()
         维度级遍历 TickingBlockEntity。原来那个切点恒为 0；现在挂 TickingBlockEntity#tick()，
         再用 getPos() 反推区块，保住"按区块"的归因粒度（老版本仍保留旧切点）。
      · 同族问题：内部派发命令（勘探传送、空置域挖掘的 /fill）原来用"反射返回值 != null"判断成功，
        而 void 方法成功也返回 null ⇒ 挖掘任务在真机上刚开就报"命令派发失败"。
        现在统一用 VanillaReflect.callMatchingQuietly（方法找得到且调用没抛异常才算成功）。
  · 新增 verify/realjar.ps1：**真机切点核对** —— 直接反编译你的 server.jar（Bundler 自动拆内层 jar +
    META-INF/libraries 里的 authlib），逐个核对切点的方法名/参数个数/返回类型与权限 API，20 项。
    这是唯一能防住"日志说已改写、功能却整块失效"的检查，换服务端版本后建议跑一次。
  · 离线自检的替身类改成与真实 26.3 一致的形状（命令入口 void、权限走 PermissionSet、
    替身里故意不提供 hasPermission(int)），这样上面这类"假绿"以后会被自检直接抓住。
  · README 增补「26.x 的真实 API」一节，把这三处差异与判断方法写清。

功能总览（一个 jar，纯服务端，不用插件 / 不用客户端 Mod）
---------------------------------------------------------
  三合一登录     正版号 + LittleSkin 等外置号 + 管理员指定 UUID 的离线号，同一台原版服务端同服；
                 失败关闭（名单内校验失败直接断开，绝不回退 Mojang）、皮肤属性强制验签
                 → README 第一、六章
  区块卡顿勘探   按区块分项采样 tick 耗时（区块 tick / 实体 / 乘客 / 方块实体 / 整服 MSPT），
                 一条命令列出异常区块的**坐标范围**，聊天里点一下 tp 到现场 → README 第七章
  管理员命令     /hy …（命令根可配，另有 ha / hyauth；/lag 是勘探快捷方式）
                 名单管理 + UUIDv7 发证前扫全服查重；控制台 / 游戏内 / RCON 全覆盖，
                 不往 Brigadier 注册节点（不会与原版或插件命令撞名）→ README 第八章
  空置域挖掘     /hy clear 对角选两点 → 预演 → 确认，服务端用原版 /fill 分三阶段节流执行、可随时中止；
                 基岩开关、边长/体积上限、权限门槛更高 → README 第九章
  配置文件       littleskin_config.json，改完保存 ~0.5s 热重载；带 config_version 与自动补齐 → README 第五章
